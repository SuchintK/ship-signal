Compare the behavior

The investigate command and weekly scheduler call Workflow::investigate. The workflow loads the saved report, selects the product's Linear scopes, and passes in-scope tickets and requested variants to the model. The report counts demand for stock alerts across variants. The model then compares the concrete proposal with each relevant Not needed issue.

A coverage value of partial means the proposal includes both rejected and distinct behavior. Rust returns a review finding as soon as it sees this result. A disjoint SMS-only proposal follows ordinary investigation.

Check expiry and weekly demand

For a full match, read the transition into the configured rejection states from Linear history. In the expiry test, a decision at 09:00 UTC on August 15 expires at 09:00 UTC on November 13. A run one second before expiry is suppressed. At expiry, the test report qualifies with 50% demand. A report that closed before expiry cannot revive the request later.

next_cutoff sets the end of the report's eligibility. Scheduled reports use the next scheduled cutoff, including weeks shortened or lengthened by daylight saving. The standalone path gives a seven-day UTC report seven days of eligibility after it closes.

Create and recheck the new ticket

Once ordinary investigation confirms the work is still eligible, the workflow appends the prior Linear issue link and the decision author's marked reason to the new proposal. The evidence section points to the saved report. The intended write gets a fresh UUID and the configured intake status.

SQLite saves the finding, its rejection evidence, and the write intent. On resume, the workflow compares the saved transition and reason with Linear and checks the weekly cutoff again. Changes send the pending item to review. Immediately before a write, SQLite records the intent as uncertain. If the response is lost, the saved UUID and uncertain status support reconciliation and hold further writes for that product.
