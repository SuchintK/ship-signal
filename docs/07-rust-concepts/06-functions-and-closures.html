Functions take inputs and produce a result

fn declares a named function. The parameter list describes its inputs, and the type after -> describes its return value. A final expression without a semicolon can supply that return value.

This deliberately simple text check is a language example, not Ship Signal’s actual classifier.

A closure is a function-like value

The syntax |message| { ... } creates a closure. The names between the bars are its parameters. A closure can also use values from the surrounding scope.

The closure captures access to keyword. This makes it possible to build a small piece of behavior and pass it to another function.

Pass the behavior into another function

impl FnOnce(&str) -> bool accepts a callable that can take the string input and return a boolean. The function invokes it once. A compatible named function can be supplied too.

FnOnce permits one call; it does not mean that every compatible closure is inherently limited to one call. Closures that support repeated calls can also satisfy this interface.

Decode the classifier parameter in Workflow::analyze

Part of the signatureMeaning
&[Feedback]A shared slice: a borrowed view of the input feedback list.
Vec<Classification>The owned list of classifications returned by the classifier.
Result<…>The operation can succeed with that list or fail with an error.
impl FnOnce(…) -> …The caller supplies a compatible callable. Analyze calls it once after reading the input.

The workflow does not hard-code a provider call into this function. It reads the feedback, calls classify, then runs the shared validation, counting, and saving behavior.

In the real CLI, the supplied closure calls the configured model through Rig. In workflow tests, a controlled classifier can return predictable classifications. This keeps the same workflow rules under both callers without requiring a live model for those tests.
