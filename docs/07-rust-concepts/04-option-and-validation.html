Option means a value may be absent

Option<T> has two forms: Some(value) holds a value of type T, and None means there is no value. It makes absence explicit in the type.

For the Option fields discussed here, JSON serialization represents Some("CSV") as "CSV" and None as null.

Absent and present-but-empty are different

Rust valueWhat the type saysShip Signal’s variant rule
NoneNo variant was supplied.Accepted.
Some(String::from("CSV"))A string was supplied.Accepted.
Some(String::from(""))A string was supplied, but it is empty.Rejected.
Some(String::from(" "))A string was supplied, containing whitespace.Rejected.

Option<String> permits all four values at the type level. The application adds the nonblank-content rule. Optional does not mean that every present value is meaningful.

Read the actual validation expression

The variant expression checks these steps:

  1. as_ref() borrows the value inside the option, producing Option<&String>. The check does not take ownership of the original string.
  2. is_none_or(...) succeeds when the option is None, or when the supplied condition succeeds for a present value.
  3. |v| !v.trim().is_empty() is the condition: after ignoring leading and trailing whitespace, the string must contain something.

trim() is used to inspect the value; this expression does not rewrite or normalize the saved string.

The check does not require a variant. It requires useful content only when a variant is supplied. If the condition is false, ensure! returns an error.

The meaning of None depends on the field

Need.variant = None means no requested variant was specified. NeedReport.identity = None means that group had no confirmed identity mapping when the report was calculated. These share the same optional-value mechanism but represent different product facts.
