Result carries either success or an error

Result<T, E> is either Ok(value), containing a success value of type T, or Err(error), containing an error of type E. A function can return Result to let its caller handle failure.

Ship Signal imports anyhow::Result, so a signature such as Result<Report> uses anyhow’s error type instead of spelling a second type parameter at every call site.

What does ? do?

On a Result, ? extracts the value from Ok. For Err, it returns an error from the current function early, converting the error type when supported. It does not ignore the failure or continue with an empty value.

The successful literal inputs make unwrap() safe in these small examples. Unwrapping an actual Err would panic; returning the error with ? lets the caller decide how to handle it.

ensure! checks a condition and returns an error if it fails

ensure!(condition, "message") means: continue if the condition is true; otherwise return an error with that message. It is a macro from anyhow, not an assertion that requires an optional field to exist. For classifier validation, it stops invalid data before saving a new report.

bail!("message") returns an error immediately. .context("message") adds explanatory context to an error. These appear alongside ? to explain which operation failed.

Follow the failure path through Analyze

If source.read fails, classification is not called. If the classifier fails, complete_analysis is not called. If validation inside complete_analysis fails, the new report is not inserted.

An early error is not an automatic rollback of all earlier work. In interactive review, confirmed mappings are saved as decisions are made. A later error returns from the operation while those earlier decisions remain saved. Only operations inside an appropriate database transaction share its rollback boundary.
