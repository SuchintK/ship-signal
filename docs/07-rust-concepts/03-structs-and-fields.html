A struct groups related named fields

A struct defines a type with named fields. Ship Signal’s Need keeps a need’s text and optional requested variant together.

The type definition says what fields exist. Need { ... } constructs a value; request.need accesses a field. String is an owned string value. Option<String> allows either an owned string or no value.

How do these fields relate to the product terms?

Rust fieldProduct meaningExample
Need.needThe human-readable underlying customer goal.Export orders
Need.variantThe particular requested behavior, if specified.Some("CSV")
NeedReport.identityThe confirmed product-scoped identity, if a mapping exists when demand is calculated.Some("export-orders")

There is no identity field in the classifier’s Need struct. The workflow looks up a confirmed mapping separately when calculating the report. The classifier, reports, review items, and mapping table all use the need field for this text.

Struct fields can contain other collections of values

Vec<Need> is a growable list of Need values. A Classification has one message index and a list of needs. A message with no explicit feature request has an empty list. Classifications wraps the list returned by the model.

A struct does not automatically create a table

These structs describe in-memory values. Serialization converts those values into a representation such as JSON. In the current implementation, feedback, classifications, and demand results are stored inside a report’s JSON column. Defining a Need struct does not create a needs SQL table.
