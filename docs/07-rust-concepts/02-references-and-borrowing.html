What does a reference do?

If a function takes ownership of a String, the caller usually cannot keep using that same owned value afterward. A reference lets the function borrow access while ownership stays with the caller.

&text creates a shared borrow. The function parameter holds a reference rather than the original String. For a function that only reads string contents, &str is usually a more flexible parameter type; &String here makes the reference-to-the-owned-value example explicit.

Two reference forms used in this code

FormMeaningDirect access through the reference
&TShared reference to a value of type T.Read it; several shared borrows may overlap.
&mut TExclusive mutable reference to a value of type T.Read or change it; incompatible borrows cannot overlap its use.

For the ordinary values in these examples, you cannot mutate through a shared reference. Some specialized Rust types support controlled “interior mutability”; that is a separate topic.

The shared borrows are no longer used when the mutable borrow begins. Rust can end a borrow after its last use; it need not last until the end of the surrounding block. The * operator dereferences write to access the borrowed integer.

Why does overlapping access fail?

Intentionally does not compile

Here the shared borrow must remain usable across the mutable borrow. Rust rejects that overlap. Move the shared read before the mutable borrow, or change the flow so the borrows do not overlap.

Does the reference binding itself need mut?

let write = &mut count; is enough to modify the borrowed value. You do not need let mut write for that. The mut inside &mut controls access to the borrowed value; mut on a binding controls mutation of that binding. Adding mut to a binding holding &T does not turn it into &mut T.

In Ship Signal: &mut source does not mean a writable database

&mut self borrows the workflow mutably. source: &mut impl FeedbackSource borrows an object that implements the feedback-source interface. Its read method can update connection state while reading records.

Rust access and database permissions are separate. The source object needs mutable access to use its client, but the PostgreSQL transaction explicitly uses read_only(true). A mutable Rust reference does not grant permission to write source records.
