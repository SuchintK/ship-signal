A binding gives a value a name

In let count = 3;, count is a binding: a name associated with a value. In everyday Rust discussion, people often call this a variable. By default, you cannot assign a different value through that binding.

mut permits mutation through this binding. It does not change the value’s type, automatically create a reference, or grant access to an external database.

Changing a value versus creating a new binding

Another let with the same name creates a new binding, called shadowing. The new binding can even have a different type. Assigning to an existing mutable binding keeps its type.

This example uses unwrap() because the literal "3" is known to parse. In code handling fallible input, use Result and error handling instead; see Results and errors.

A variable can hold a value or a reference

A reference is a value that borrows access to another value. A binding can hold an owned value, a shared reference, or a mutable reference. “Variable” and “reference” describe different aspects of the code.

CodeWhat the binding holdsWhat it permits
let mut count = 10;An integer value.Change count.
let read = &count;A shared reference to the integer.Read the integer through read.
let write = &mut count;An exclusive mutable reference to the integer.Change the integer through write.

The reference declarations above illustrate the types of binding; their allowed overlap depends on how the references are used. The references lesson shows a complete valid example.

The mut classifications parameter allows the function to reorder its owned vector. sort_by_key changes that vector’s order in place. The classification count is checked before sorting.
